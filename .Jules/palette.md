## 2024-08-24 - Accessibility state attributes and hidden labels
**Learning:** Found that the responsive mobile menu toggle button (`apps/web/src/components/layout/app-shell.tsx`) was missing `aria-expanded` to communicate its state to screen readers. Also, discovered that the chat input field (`apps/web/src/app/projects/repo-chat.tsx`) lacked an explicit `<label>`, so using `aria-label` provides a hidden label that screen readers can rely on.
**Action:** Ensure dynamic UI components explicitly declare their open/closed states using `aria-expanded`, and always provide an `aria-label` to form fields without an explicit visual label.

## 2024-09-01 - Form error association and screen reader announcements
**Learning:** Found that the repository connection form (`apps/web/src/app/projects/connect-github-form.tsx`) did not associate its dynamic error or success messages with the input field, meaning screen readers would not contextually announce the result of a failed or successful action. The required nature of the field was also not explicitly communicated.
**Action:** When adding validation or state messages to inputs, use `aria-describedby` to link the input to the message element, use `aria-invalid` to indicate error state, and provide `role="alert"` or `role="status"` on the message elements so they are announced dynamically. Also ensure required fields are marked with `required` attribute and have accessible text indicating they are required.
